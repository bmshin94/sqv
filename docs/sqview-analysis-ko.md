## 1. 이게 뭐하는 프로젝트인가

한 줄 요약: **터미널에서 돌아가는 SQLite 데이터베이스 뷰어 겸 편집기**

- SQLite 파일(`.db`, `.sqlite`)은 그냥 열면 읽을 수 없는 이진 파일이다.
- sqview는 이 파일을 터미널 안에서 **엑셀 같은 표 형태**로 보여주고 편집까지 지원한다.
- GUI 툴(DB Browser 등)을 쓸 수 없는 환경(SSH 원격 서버 등)에서 특히 유용하다.

### 기술 스택

| 항목 | 내용 |
|---|---|
| 언어 | Rust (edition 2021) |
| TUI | `ratatui` 0.29 + `crossterm` 0.28 |
| DB | `rusqlite` 0.32 (bundled) + `r2d2` 커넥션 풀 |
| 비동기 | `tokio` (33ms 틱 = 30Hz 렌더 루프) |
| 파일 감시 | `notify` 7 |
| CLI | `clap` 4 |
| 규모 | 소스 20,917줄 / 테스트 214개 / 직접 의존성 24개 |

### 주요 기능

- 가상 스크롤 — 대용량 테이블도 버벅임 없이 탐색 (`src/grid/virtual_scroll.rs`)
- 셀 직접 편집 — 텍스트 / 날짜 / 시간 / enum / 외래키별 전용 팝업 편집기
- 외래키 점프 — `j`로 연결된 테이블로 이동, `Backspace`로 복귀
- 컬럼별 필터 + 정렬 + 정규식(REGEXP) 지원
- 알파벳 레일 — 글자 눌러서 해당 위치로 점프
- CSV / JSON / SQL 내보내기
- 외부에서 DB 파일이 바뀌면 자동 새로고침
- 읽기 전용 모드(`--readonly`), Undo(`Ctrl-z`)
- 테마 · 아이콘 전부 `config.toml`에서 커스터마이즈 (OSC 11로 터미널 배경색까지 변경)

### 저장소 구조에서 눈여겨볼 것

| 경로 | 왜 중요한가 |
|---|---|
| `DECISIONS.md` | 왜 sqlx 대신 rusqlite를 썼는지 등 **설계 결정의 이유**를 기록 |
| `docs/audits/` | 코드 감사 리포트(37KB). **실제 버그 13개를 찾아내고 고친 기록** |

| `examples/chinook.db` | 바로 실행해볼 수 있는 샘플 DB |

## 2. 설치 및 사용법

### 설치

```bash
# 방법 A: 데비안 패키지 (우분투/데비안, 가장 쉬움)
tmp_deb="$(mktemp /tmp/sqview.XXXXXX.deb)"
curl -fL -o "$tmp_deb" \
  https://github.com/mendrik-private/sqv/releases/latest/download/sqview-linux-amd64.deb
sudo apt install "$tmp_deb"

# 방법 B: 바이너리 직접 설치
curl -fL -o sqview.tar.gz \
  https://github.com/mendrik-private/sqv/releases/latest/download/sqview-linux-x86_64.tar.gz
tar -xzf sqview.tar.gz
sudo install -m 0755 sqview /usr/local/bin/sqview

# 방법 C: 소스 빌드 (이 저장소에서)
cargo install --path . --bin sqview
```

> 명령어 이름은 `sqv`가 아니라 **`sqview`** 다. 우분투의 OpenPGP 도구 `sqv`와
> 이름이 겹치는 것을 피하기 위함이다.
>
> 공식 릴리즈 바이너리는 **리눅스 x86_64만** 제공된다. macOS / Windows는 직접 빌드해야 한다.

### 실행

```bash
sqview mydata.db              # 기본 실행
sqview mydata.db --readonly   # 읽기 전용 (쓰기 차단)
sqview mydata.db --no-watch   # 파일 변경 자동 감지 끄기
sqview :memory:               # 빈 메모리 DB (연습용)
sqview check-terminal         # 터미널 색상/마우스 지원 여부 확인
sqview paths                  # 설정/데이터/필터 경로 출력

# 샘플 DB로 바로 체험
cargo run --release -- examples/chinook.db
```

## 3. 플러그인인가, 스킬인가, MCP인가?

**셋 다 아니다. 독립 실행형 CLI 프로그램이다.**

| 종류 | 정의 |
|---|---|
| 플러그인 | Claude Code에 기능을 추가하는 묶음 |
| 스킬 | AI에게 "이럴 땐 이렇게 하라"고 알려주는 지시서 |
| MCP | AI가 외부 도구·데이터에 연결하는 **프로토콜 규격** |
| **sqview** | `git`, `vim`처럼 혼자 돌아가는 터미널 프로그램 |

헷갈리기 쉬운 이유는 저장소에 `CLAUDE.md`와 `skills-lock.json`이 들어 있기 때문이다.
이건 **이 프로그램이 AI로 개발되었다는 흔적**일 뿐, 프로그램 자체가 AI용이라는 뜻은 아니다.

> 정리: sqview는 "AI가 만든 프로그램"이지 "AI용 프로그램"이 아니다.

## 4. API 토큰이 필요한가?

**전혀 필요 없다. 100% 오프라인으로 동작한다.**

소스 전체를 검사한 결과:

- HTTP 클라이언트 라이브러리 없음 (reqwest, hyper 등 미사용)
- API 키 / 토큰 관련 코드 없음
- 외부 AI 서비스 호출 없음
- **네트워크 코드 자체가 존재하지 않음**

이는 보안 측면에서 강점이다. 고객 데이터가 든 DB를 열어도 **데이터가 외부로 전송되지 않는다.**
클라우드 기반 DB 툴을 쓸 수 없는 규제 산업(의료·금융·공공)에서 의미 있는 차별점이다.

## 6. 로컬 에이전트 구축에 도움이 되는가

**직접 활용: 어렵다.** AI 에이전트는 텍스트를 주고받는데, sqview는 화면에 표를 그리는
TUI라서 출력이 파싱에 적합하지 않다. 에이전트용으로는 `sqlite3` CLI가 낫다.

**간접 활용: 매우 유용하다.**

### (1) 코드를 재활용해 MCP 서버 만들기 — 가장 실전적

이미 구현되어 있는 부분들이 그대로 에이전트 안전장치의 재료가 된다.

| sqview 구성요소 | 에이전트에서의 역할 |
|---|---|
| `src/db/schema.rs` | AI에게 DB 구조를 알려주기 |
| `src/db/write.rs` | 안전한 쓰기 (트랜잭션 · 검증) |
| `--readonly` 모드 | **AI에게 읽기 권한만 부여** |
| `src/filter/predicate.rs` | SQL 인젝션 방어 |
| Undo 기능 | AI 실수 롤백 |

### (2) AI 작업 실시간 모니터링

`notify` 기반 파일 감시 덕분에, 에이전트가 DB를 변경하면 화면이 자동 갱신된다.
터미널 하나를 띄워두고 AI가 무엇을 바꾸는지 실시간으로 볼 수 있다.

### (3) "AI로 개발하는 법" 교재

`DECISIONS.md`(설계 원칙으로 AI 이탈 방지), `docs/audits/`(AI 코드를 감사해
버그 13개 발견·수정한 실전 기록)는 에이전트 기반 개발 워크플로의 좋은 참고 자료다.

감사 리포트에서 발견된 대표 사례:
- 선언된 `rowid` 컬럼 때문에 한 행 삭제가 여러 행을 삭제할 수 있음
- 잘못된 숫자 입력이 조용히 `NULL`로 커밋됨
- 필터 상태 저장 경로에 경로 탐색(traversal) 여지가 있음

## 7. 수익화 아이디어

### 시장 진단 (먼저 알아야 할 것)

"SQLite 뷰어"라는 카테고리는 이미 무료 제품으로 포화 상태다.

| 경쟁자 | 가격 | 위협도 |
|---|---|---|
| DB Browser for SQLite | 무료 | 매우 높음 |
| Drizzle / Prisma Studio | 무료 | 높음 |
| Adminer / sqlite-web | 무료 | 높음 |
| TablePlus | ~$89 | 중간 |
| DBeaver / Beekeeper | 무료 + 유료 | 중간 |
| Harlequin / litecli | 무료 | 중간 |

**결론: 같은 제품을 만들어 돈을 받는 접근은 성립하지 않는다. 각도를 바꿔야 한다.**

### 수익화 3원칙

1. 개발자 개인은 지갑이 얇고, 기업은 두껍다
2. "편리함"은 싸고, "사고 방지 · 규정 준수"는 비싸다
3. 도구보다 "도구를 쓰는 법"(콘텐츠)이 더 잘 팔린다

### 아이디어 비교표

| # | 아이디어 | 난이도 | 투자금 | 회수기간 | 최대수익 | 추천도 |
|---|---|---|---|---|---|---|
| 1 | 콘텐츠 (AI 개발 교재) | ★★ | 0원 | 3~6개월 | 중~높음 | ★★★★★ |
| 2 | MCP 서버 (AI DB 안전장치) | ★★★★ | 소액 | 6~12개월 | 매우 높음 | ★★★★★ |

| 4 | 모바일 앱 SQLite 디버거 | ★★★★ | 소액 | 6개월 | 중간 | ★★★ |

> 아래 수익 수치는 모두 **추정치**이며, 실행력과 마케팅에 따라 크게 달라진다.

### 1) 콘텐츠 — "AI로 만든 2만 줄 프로젝트 해부"

sqview 자체가 아니라 **"이걸 어떻게 만들었는가"**를 판다.

- 차별점: 시중 콘텐츠는 대부분 To-do 앱 수준. 이건 실제 배포된 2만 줄 프로젝트 +
  설계 문서 + 감사 리포트까지 갖췄다.
- 채널: 유튜브/블로그(무료, 청중 확보) → 전자책(2~3만원) → 온라인 강의(8~15만원) → 멘토링
- 추정: 1~3개월 수익 0원 → 4~6개월 월 30~100만원 → 7~12개월 월 100~500만원
- 리스크: 꾸준함이 전부. 또한 **오빠가 원저자가 아니므로 "이 오픈소스를 분석한다"로
  정직하게 포지셔닝해야 한다.**

### 2) MCP 서버 — "AI에게 DB를 안전하게 맡기는 법"

```
[AI 에이전트] → [MCP 게이트웨이] → [회사 DB]
                      ↑
             DROP TABLE 차단 / 쓰기 승인 / 감사 로그
```

- 해결하는 고통: "AI에게 DB 권한을 주고 싶은데 사고 나면 어쩌지?" — AI 도입의 1순위 걸림돌
- 가격: 무료 오픈소스(입소문) / 팀 월 $30~99 / 기업 연 $5,000~30,000
- 추정: 6~12개월 월 50~500만원, 기업 계약 시 연 수천만원 가능
- **리스크(중요): 이미 무료 SQLite MCP 서버가 존재한다. 단순 "SQLite MCP"로는 차별화
  불가. 반드시 안전 · 감사 · 권한 관리 쪽으로 파고들어야 한다.**

### 3) 웹 SaaS — 비개발자용 SQLite 편집기

- 타겟: 개발자가 아니라 **기획자 / PM / 디자이너 / QA / 분석 입문자**
- 기술: `sql.js`(WebAssembly)로 브라우저 안에서 실행 → 서버 비용 거의 0, "데이터가
  서버로 안 올라감"이 세일즈 포인트
- 가격: 무료(10MB) / 프로 $7월 / 팀 $25인월
- 추정: 월 1만 방문 × 전환율 1~2% → 월 100~200만원
- 리스크: 유사 서비스 다수. **팀 공유 · 히스토리 같은 협업 기능만이 유료화 명분**

### 4) 모바일 앱 개발자용 디버거

- 고통: `adb pull` → 뷰어로 열기 → 수정 → `adb push` → 앱 재시작 (매번 5분)
- 제안: 앱 실행 중 실시간 조회·수정 (10초)
- 가격: 개인 $29~49 평생 / 팀 연 $199~
- 강점: 고통이 매일 발생하고 구체적이라 지불 의사가 명확, 타겟 커뮤니티가 뚜렷
- 리스크: Flipper, Stetho 등 무료 대안 존재. iOS/Android 양쪽 대응 필요

### 5) 셀프호스팅 "SQLite판 phpMyAdmin"

- 배경: MySQL엔 phpMyAdmin, Postgres엔 pgAdmin이 있지만 SQLite엔 마땅한 운영 도구가 없다.
  Turso / LiteFS / Cloudflare D1 등으로 SQLite를 운영 DB로 쓰는 흐름이 커지는 중.
- 기능: 웹 UI(도커 한 줄), 백업·복구, 마이그레이션, 권한, 감사 로그, 슬로우 쿼리
- 가격: 무료 셀프호스팅 + 기업판 연 $2,000~10,000
- 리스크: 아직 시장이 작다. 다만 성장 중이라 선점 효과를 노릴 수 있다.

### 6) 규제 산업 온프레미스 — "데이터가 밖으로 나가지 않음"

- 근거: 4번 항목에서 확인했듯 **네트워크 코드가 0줄**이다. 망분리 환경에서 그대로 쓸 수 있다.
- 타겟: 병원, 금융, 공공기관, 방위산업, 법무법인
- 가격: 사이트 라이선스 연 1,000~5,000만원 + 커스터마이징/교육/지원 별도
- 리스크: 기술이 아니라 **영업·신뢰·조달 절차 싸움**. 혼자서는 사실상 불가능, 파트너 필요

### 7) 오픈코어 데스크탑 유료판

- 무료: 현재 기능 / 프로($39 평생): 쿼리 히스토리, 팀 설정 공유, **macOS·Windows 공식 빌드**,
  스키마 다이어그램
- 추정: 월 5~30개 판매 → 월 20~150만원
- **솔직한 평가: 시간 대비 효율이 가장 낮다.** DB Browser가 무료라 지불 명분이 약하고,
  결제·환불·지원 응대 부담이 크다.

### 8) 외주 · 커스터마이징

## 8. 추천 전략: 1번 + 2번 조합

```
콘텐츠(1번)로 청중을 모으고
        ↓ 신뢰 + 잠재고객
MCP 서버(2번)를 그 청중에게 판매
```

**시너지 근거**
1. 콘텐츠 제작 과정이 곧 제품 홍보가 된다
2. 제품 출시 전에 이미 고객(구독자)을 확보한다
3. 둘 다 투자금 0원 — 실패 비용이 시간뿐이다
4. 콘텐츠가 먼저 수익화되어 버틸 체력이 생긴다
5. "AI로 개발" ↔ "AI를 안전하게" — 소재와 청중이 겹친다

## 부록: React / PHP로 다시 만든다면

| 항목 | Rust (현재) | React | PHP |
|---|---|---|---|
| 실행 환경 | 터미널 | 브라우저 | 브라우저 |
| 구현 난이도 | 어려움 | 중간 | 쉬움 |
| 속도 | 최상 | 보통 | 보통 |
| SSH 원격 서버 | 가능 | 불가 | 웹서버 필요 |
| 비개발자 접근성 | 낮음 | 높음 | 높음 |
| 수익화 용이성 | 낮음 | 높음 | 높음 |

- **React**: `sql.js`로 브라우저 내 SQLite 실행 + `TanStack Table`/`AG Grid` +
  `TanStack Virtual`. sqview가 직접 구현한 가상 스크롤·컬럼 폭 계산·팝업 편집기가
  전부 기성 라이브러리로 대체된다. 필터→SQL 변환 로직은 `src/filter/predicate.rs` 참고.
- **PHP**: `PDO('sqlite:...')` 한 줄로 연결된다. Adminer(단일 PHP 파일로 DB 관리)라는
  전례가 있어 구현이 가장 쉽다.

수익화가 목표라면 **React 웹 버전**이 유리하다. 터미널을 쓰지 못하는 비개발자 시장이
훨씬 크고, 구독 결제 연동과 링크 기반 홍보가 쉽기 때문이다.
